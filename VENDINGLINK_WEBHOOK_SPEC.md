# VendingLink Bridge - Webhook Specification

This document describes the webhook endpoint that VendingLink must implement to receive stock from the Bridge.

## Endpoint Details

**URL:** `POST /api/bridge/webhook/stock/topup` (configurable via `VENDINGLINK_URL` env variable in the Bridge)
**Content-Type:** `application/json`
**Authorization:** `Bearer <BRIDGE_SECRET_KEY>`

## Request Headers

- `Authorization: Bearer <BRIDGE_SECRET_KEY>`: Used by VendingLink to authenticate the request from the Bridge.
- `Idempotency-Key: <transaction_id>`: Can be used by VendingLink to prevent double-processing.

## Request Payload

```json
{
  "transaction_id": "BRG-20261005-A1B2C3",
  "product_id": "RZK-6a2fda51035a6d898f2106fe",
  "supplier_code": "RZK",
  "supplier_product_id": "6a2fda51035a6d898f2106fe",
  "added_qty": 10,
  "items": ["<encrypted_key1>", "<encrypted_key2>"],
  "source": "BRIDGE_BOT"
}
```

### Fields

- `transaction_id` (string): Unique identifier for this transaction generated by the Bridge.
- `product_id` (string): The Namespaced VendingLink Product ID. Format: `<SUPPLIER_CODE>-<SUPPLIER_PRODUCT_ID>`.
- `supplier_code` (string): The code of the supplier (e.g., `RZK`).
- `supplier_product_id` (string): The raw product ID from the supplier.
- `added_qty` (integer): The number of items purchased.
- `items` (array of strings): The actual keys/accounts received from the supplier.
- `source` (string): Hardcoded to `"BRIDGE_BOT"`.

## Expected Responses

VendingLink should respond to the Bridge's HTTP POST request with appropriate HTTP status codes:

- **200 OK / 201 Created / 204 No Content:** The stock was successfully added to VendingLink. The Bridge will mark the transaction as `COMPLETED`.
- **409 Conflict:** The `transaction_id` or `Idempotency-Key` has already been processed. The Bridge will treat this as a success and mark the transaction as `COMPLETED`.
- **5xx Server Error / 429 Too Many Requests:** Temporary failure on VendingLink's side. The Bridge will automatically retry with exponential backoff.
- **Other 4xx Errors (e.g., 400, 401, 404):** Non-retryable error (e.g., product doesn't exist in VendingLink). The Bridge will mark the transaction for manual review (`NEEDS_REVIEW`) and alert the admin.
