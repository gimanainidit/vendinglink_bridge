# VendingLink Bridge - Webhook Specification

This document describes the webhook endpoint that VendingLink must implement to receive stock from the Bridge.

## Endpoint Details

**URL:** `POST /api/bridge/webhook/stock/topup` (configurable via `VENDINGLINK_URL` env variable in the Bridge)
**Content-Type:** `application/json`
**Authorization:** `Bearer <BRIDGE_SECRET_KEY>`

## Request Headers

- `Authorization: Bearer <BRIDGE_SECRET_KEY>`: Used by VendingLink to authenticate the request from the Bridge.
- `Idempotency-Key: <transaction_id>`: Can be used by VendingLink to prevent double-processing.

## Request Payload

```json
{
  "transaction_id": "BRG-20261005-A1B2C3",
  "product_id": "RZK-6a2fda51035a6d898f2106fe",
  "supplier_code": "RZK",
  "supplier_product_id": "6a2fda51035a6d898f2106fe",
  "added_qty": 10,
  "items": ["<encrypted_key1>", "<encrypted_key2>"],
  "source": "BRIDGE_BOT"
}
```

### Fields

### Fields

- `transaction_id` (string): Unique identifier for this transaction generated by the Bridge (e.g., `BRG-20261011-EP1IC0`).
- `product_id` (string): VendingLink product ID resolved from Bridge's `ProductMapping` table. Sentinel `"[UNMAPPED]"` or `"[UNKNOWN]"` will trigger a 400 rejection from Storefront.
- `supplier_code` (string): The code of the supplier (e.g., `RZK`).
- `supplier_product_id` (string): The raw product ID from the supplier (e.g., `loc_test1`).
- `added_qty` (integer): The number of items purchased (`1 <= added_qty <= 100`, must match `items.length`).
- `items` (array of strings): The actual keys/accounts received from the supplier.
- `source` (string): Hardcoded to `"BRIDGE_BOT"`.

## Expected Responses

VendingLink should respond to the Bridge's HTTP POST request with appropriate HTTP status codes:

- **201 Created (or 200 OK / 204 No Content):** Top-up successful. Bridge will mark the transaction as `COMPLETED`.
- **409 Conflict:** Idempotent replay:
  - If `existingEvent.status === "COMPLETED"`: Bridge acknowledges delivery as completed.
  - If `existingEvent.status === "PROCESSING"`: Bridge will retry with exponential backoff until processed.
- **400 Bad Request:** Payload schema error, `Idempotency-Key` mismatch with `transaction_id`, or sentinel `[UNMAPPED]` / `[UNKNOWN]`. Bridge marks the transaction as `NEEDS_REVIEW` and notifies admin.
- **401 Unauthorized / 403 Forbidden:** Bearer token invalid or IP not in Storefront allowlist.
- **5xx Server Error / 429 Too Many Requests:** Temporary failure or rate limited. Bridge will automatically retry with exponential backoff.

## Webhook 2: Request Status Update (P2a Agentic Purchasing)

Webhook endpoint on Storefront to receive asynchronous status updates when a customer's product request is processed by the Bridge multi-supplier search worker.

### Endpoint Details

- **URL:** `POST /api/bridge/webhook/request-update` (configurable via `VENDINGLINK_URL` env variable)
- **Content-Type:** `application/json`
- **Authorization:** `Bearer <BRIDGE_SECRET_KEY>`

### Request Payload

```json
{
  "requestId": "cmv3seh020002nfm8vaf3rd5n",
  "customerRef": "cust_cuid_98765",
  "status": "FOUND",
  "query": "Canva Pro 1 bulan",
  "categorySlug": "design-tools",
  "foundSupplierCode": "PDA",
  "foundProductId": "pda_canva",
  "quotedPrice": 25000,
  "rejectionReason": null
}
```

### Fields

- `requestId` (string): Unique identifier for the ProductRequest in Bridge DB.
- `customerRef` (string): Opaque customer identifier provided by Storefront (never PII).
- `status` (string):
  - `FOUND`: Product found across active suppliers (`RZK`, `PDA`, `DAI`) with lowest quoted price and stock in stock.
  - `NOT_FOUND`: No matching stock available or price exceeds `maxBudget`.
  - `REJECTED`: Autonomous procurement rejected by safety guardrails (daily cap, per-request cap, or kill switch).
- `query` (string): Original search keyword.
- `categorySlug` (string, optional): Product category slug.
- `foundSupplierCode` (string, optional): Winning supplier (`RZK`, `PDA`, `DAI`).
- `foundProductId` (string, optional): Product SKU at winning supplier.
- `quotedPrice` (number, optional): Best quoted price from winning supplier.
- `rejectionReason` (string, optional): Explanation if status is `NOT_FOUND` or `REJECTED`.

### Expected Responses

- **200 OK:** Storefront acknowledges receipt. Storefront should forward quotation to customer.
- **401 Unauthorized:** Invalid or missing `BRIDGE_SECRET_KEY`.
